## 1. What Was Built

### 1.1 Domain Models (`packages/domain`)
- **Review & Merge Data Models (`bom.py`)**:
  - `Question`: Structured user questions for ambiguous mappings, property conflicts, or unclassified items (`id`, `kind`, `prompt`, `options`, `default`, `rule_ids`, `blocking`, `line_id`, `cad_value`, `user_value`, `status`, `answer`).
  - `Suggestion`: Additions or modifications proposed by deterministic rules or CAD discovery (`id`, `line_id`, `action`, `field`, `value`, `confidence`, `rule_ids`, `reason`, `cls`, `qty`, `uom`, `description`, `status`).
  - `ColumnMapping`: Field mapping result for a single spreadsheet column (`source_header`, `field`, `confidence`, `rule_id`, `sample_values`).
  - `TableMapping`: Table boundary and column mapping metadata (`header_row`, `first_data_row`, `last_data_row`, `columns`, `unmapped_columns`, `ambiguous_columns`, `title_block_rows`, `footer_rows`, `confidence`).
  - `UserBomRow`: Extracted and normalized user BoM row (`row_idx`, `part_number`, `description`, `qty`, `uom`, `uom_raw`, `level`, `find_no`, `refdes`, `material`, `supplier`, `supplier_pn`, `raw`).
  - `DatasheetSpec`: Technical specifications parsed from component datasheets (`spec_family`, `property_name`, `value`, `unit`, `tolerance`, `confidence`, `rule_id`, `ref`).
  - `PhotoFinding`: Qualitative visual observations (`finding_type`, `observation`, `confidence`, `rule_id`, `ref`).
- **Export & TypeScript Types (`export_schema.py` & `packages/ts-types`)**:
  - Exported schemas for `Question`, `Suggestion`, `TableMapping`, `ColumnMapping`, `UserBomRow`, `DatasheetSpec`, and `PhotoFinding`.
  - Regenerated TypeScript definition files for frontend integration.

### 1.2 BoM File Intake (`packages/rules/src/c2b_rules/bom_intake.py`)
- **Table Boundary Detection**:
  - Scans XLSX/XLS (via `openpyxl`) and CSV files.
  - Identifies metadata/title block rows, locates the primary table header row by matching candidate columns against `library/headers.yaml`, and detects trailing footers (notes, approvals, signatures).
- **Rule-Based Header Scoring**:
  - Scores column headers using regex synonyms from `library/headers.yaml` plus data-type value heuristics (e.g. numeric columns for quantity, alphanumeric patterns for part numbers).
  - Normalizes header names to canonical fields (`part_number`, `description`, `qty`, `uom`, `level`, `find_no`, `refdes`, `material`, `supplier`, `supplier_pn`).
- **Ambiguous Column Detection**:
  - Columns scoring equally for multiple fields (such as column "Item" matching both `find_no` and `part_number` with score 0.70) are flagged in `ambiguous_columns` and raised as a mapping question (placeholder for L3).
- **Data Normalisation**:
  - Quantities parsed as floats/integers.
  - Units mapped to standard library units via `units.yaml` (e.g. `'pcs'`, `'nos'` $\to$ `'EA'`) while preserving the original raw unit string in `uom_raw`.
  - Canonical part numbers trimmed of leading/trailing whitespace.
  - Hierarchical levels extracted from indented text, dots (e.g. `.1`, `..2`), or dedicated level columns.
  - Reference designator expansion: range strings like `R1-R4, R7` expand into discrete designators `['R1', 'R2', 'R3', 'R4', 'R7']`.
- **Verbatim Raw Preservation (Rule 5)**:
  - Every row stores the complete unmodified dictionary of cell values in `raw`.

### 1.3 Datasheet PDF Extraction (`packages/rules/src/c2b_rules/datasheets.py`)
- **PDF Extraction via `pdfplumber`**:
  - Extracts text and tabular data across pages.
  - Applies regex pattern extractors across 8 spec families:
    1. `dimensions`: Overall dimensions, mounting hole spacing.
    2. `mass`: Weight, net mass with unit conversion.
    3. `voltage`: Operating voltage, input/output ratings (V, VAC, VDC).
    4. `current`: Rated current, max load (A, mA).
    5. `power`: Power ratings (W, kW, mW).
    6. `ip_rating`: Ingress protection codes (e.g. IP54, IP65, IP68).
    7. `standards`: Regulatory and safety standards (e.g. CE, RoHS, UL 94, ISO).
    8. `materials`: Flame rating, enclosure materials (e.g. ABS, Polycarbonate).
- **Provenance**:
  - Every extracted spec records the exact source reference: `pdf:<filename>#p<page>`.

### 1.4 Photo Intake & Vision Router Stub (`packages/rules/src/c2b_rules/vision.py`)
- **Opt-in Control**:
  - Photo processing is strictly opt-in; no vision calls run unless explicitly enabled for the job.
- **Vision Router Stub**:
  - Implements the `vision` role interface with cassette replay support for deterministic golden runs.
- **Constraints Compliance**:
  - Confidence capped at $\le 0.40$ (`R-VIS-001`).
  - Strict compliance with Non-negotiable Rule 2: vision findings provide qualitative observations (finish, color, label text) but **never produce numbers that end up in the BoM**.

### 1.5 4-Step Merge Engine (`packages/rules/src/c2b_rules/merger.py`)
- **Matching Order (`docs/04 §7.2`)**:
  1. **Canonical Part Number Match**: Normalized exact part number comparison.
  2. **Standard Designation Match**: Standard key matching (e.g. ISO 4762 M4x12).
  3. **Normalized Description Match**: Description and CAD node name normalized matching.
  4. **Reference Designator Match**: Electrical reference designators (`refdes`).
- **Outcomes & Rules**:
  - **User Lines Never Rewritten (Rule 5)**: User BoM lines are accepted verbatim. When user and CAD properties conflict (e.g. user quantity 6 vs CAD instance count 4 for `SCR-1004`), the line keeps the user's value (6), and a blocking `Question` (`Q-001`) is recorded showing both values and sources.
  - **CAD Parts Missing from User BoM**: Leaf parts present in CAD but absent from the user BoM generate `Suggestion` items (`action="add"`). Phantoms (such as `FASTENERS_GRP`) are filtered out, ensuring suggestions are only created for physical parts (`Shaft`, `Part2` washer, `Part3` nut).
  - **Unmatched User Lines**: Preserved with provenance `source="bom_file"`, flagging CAD absence for review.
- **Deterministic Pipeline Integration (`engine.py`)**:
  - Extended `build_ebom(...)` to coordinate CAD extraction, user BoM normalization, datasheet extraction, photo analysis, and the 4-step merge.

### 1.6 Worker, API & Web UI Integration
- **Worker Tasks (`apps/worker/src/c2b_worker/tasks.py`)**:
  - Extended `run_pipeline` and `_build_bom_for_job` to handle BoM-only jobs (B4) and CAD+BoM hybrid jobs (B5).
  - Emits Step 7 (User BoM and file merge) checkpoints and job events.
- **Job Repository (`packages/jobs/src/c2b_jobs/repo.py`)**:
  - Added `answer_question` and `review_suggestion` methods with status updating and event logging.
- **API Endpoints (`apps/api/src/c2b_api/jobs.py`)**:
  - `GET /jobs/{job_id}/mapping`: Returns detected `TableMapping`.
  - `POST /jobs/{job_id}/mapping/confirm`: Saves confirmed column mappings.
  - `POST /jobs/{job_id}/questions/{question_id}/answer`: Records user answers to open questions.
  - `POST /jobs/{job_id}/suggestions/{suggestion_id}`: Records acceptance or rejection of suggestions.
- **Frontend Screen (`apps/web/src/screens/MappingConfirm.tsx`)**:
  - Clean, accessible table mapping confirmation screen with column dropdowns, preview table, and ambiguous column alerts.
  - Connected into `JobUpload.tsx` banner and client routing in `App.tsx`.

## 4. Architectural Notes & Rule Compliance

1. **Non-Negotiable Rule 1 & 5 Compliance**:
   - Zero LLM calls in intake and merge. All header mapping, normalisation, matching, and question generation use deterministic rules.
   - User BoM rows are never overwritten or rewritten. Original cell values are preserved verbatim in `raw`.
2. **Non-Negotiable Rule 2 & 4 Compliance**:
   - Vision router findings are qualitative only, capped at confidence $\le 0.40$, and never inject numbers into the BoM.
   - Every value carries provenance (`source`, `confidence`, `rule_ids`, `ref`).
3. **Data Parity with Golden Contract**:
   - Leading/trailing whitespace in part numbers is preserved in `raw` but trimmed in canonical `part_number`.
   - Unit synonyms (`pcs`, `nos`) map to standard `EA` while preserving `uom_raw`.
4. **Git Hygiene (Owner Rule 2)**:
   - All Phase 4 code, types, migrations, endpoints, and frontend components remain in the working tree. No commits, merges, or pushes were executed.
