## 1. What Was Built

### 1.1 LiteLLM Router (`packages/agents/src/c2b_agents/router.py`)
- **Multi-Role Routing (ADR-009, `docs/02 §4`)**:
  - Four distinct roles:
    - `reasoner`: `groq/llama-3.3-70b-versatile` (fallback: `gemini/gemini-1.5-pro`)
    - `extractor`: `groq/llama-3.1-8b-instant` (fallback: `gemini/gemini-1.5-flash`)
    - `vision`: `gemini/gemini-1.5-flash`
    - `agent`: `groq/llama-3.3-70b-versatile` (fallback: `gemini/gemini-1.5-flash`)
- **Rate Limiting & Resilience**:
  - In-memory `TokenBucket` tracking RPM and TPM per role.
  - Exponential backoff with jitter on HTTP 429 rate limit responses, with automatic failover to the configured fallback role.
  - Per-job token budget enforcement (default 40,000 tokens per job).
- **Audit Logging & Provenance**:
  - Logs every LLM invocation with `job_id`, `role`, `model`, `prompt_tokens`, `completion_tokens`, `total_tokens`, `latency_ms`, `fallback_reason`, `line_id`, and `cassette_key`.
  - Database persistence via `llm_call` PostgreSQL migration table and `c2b_jobs.repo.record_llm_call`.
- **Deterministic Cassettes (`cassettes.py`)**:
  - Cassette store keyed by SHA-256 hash of `(role, prompt, schema_name)`.
  - Full recording and replaying capabilities for CI/testing without external network dependencies or API keys.

### 1.2 Constrained Fallback Ladder L1–L6 (`packages/agents/src/c2b_agents/ladder.py`)
- **Dynamic Library Schema Constraints (`schemas.py`)**:
  - Structured output models generated dynamically using closed enums from the active `library/`:
    - Taxonomy codes from `library/taxonomy.yaml` (~397 classes).
    - Material families from `library/materials/`.
    - Canonical header fields from `library/headers.yaml`.
- **Ladder Steps**:
  - **L1 (Classify Part)**: Invoked when rule classification confidence < 0.75 or part is unclassified. Output class is constrained to valid taxonomy codes. Sets `source="llm"`, caps confidence at 0.70, sets `R-CLS-LLM`, and adds notice to `open_items`.
  - **L2 (Material Family)**: Proposes material family when drawing or metadata is incomplete. Returned as low-confidence suggestion.
  - **L3 (Header Mapping)**: Maps ambiguous or unmapped spreadsheet column headers (such as column "Item" scoring equally for `find_no` and `description`).
  - **L4 (Gap Candidates)**: Identifies missing standard items commonly required for unknown products (e.g. labels, manuals, packaging cartons, assembly screws). Returned as suggestions with confidence 0.40.
  - **L5 (Description Vocabulary)**: Formulates noun-first descriptions when class modifiers lack standardized vocabulary.
  - **L6 (Datasheet Field Extraction)**: Extracts specific electrical/mechanical ratings from datasheet text snippets.
- **L6 Acceptance Rule**:
  - Requires that the exact extracted `value` appears verbatim inside the extracted `quote`. If not found, the extraction is rejected and converted into a user `Question`.
- **Failsafe Ladder Principle**:
  - If any LLM role fails, times out, or exceeds budget, the operation converts deterministically into a user `Question`.

### 1.3 Grounded Chat Agent (`packages/agents/src/c2b_agents/agent.py`)
- **LangGraph Conversational Workflow (ADR-008)**:
  - Small directed state machine: `START` -> `classify_intent` -> `process_query` -> `extract_suggestions` -> `END`.
- **Suggestions-Only Contract (Non-negotiable Rule 5)**:
  - The chat agent NEVER modifies BoM lines directly. Any change request (e.g. "make all M4 screws stainless") returns `Suggestion` objects with `review="suggested"` that require user review.
- **Determinism & Grounding**:
  - Job summaries (`generate_job_summary`) are computed directly from BoM counts and open items.
  - Plain-words line explanations (`explain_line_in_plain_words`) translate deterministic rule traces into readable Markdown.
- **API Endpoint**:
  - `POST /jobs/{job_id}/chat` returns `{reply: str, suggestions: list[Suggestion], line_refs: list[str]}`.
