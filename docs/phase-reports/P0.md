## Defects found by e2e and fixed

1. Caddy would not start: the stock binary has a file capability (`cap_net_bind_service`) that cannot be exec'd with `cap_drop: ALL`. Fixed by removing the capability in `apps/web/Dockerfile` (we listen on 8080).
2. Race in `POST /start`: status only changed when the worker ran, so a quick second call was accepted. Fixed with an atomic `uploading → extracting` update in the API (`repo.claim_start`); the worker still sets it idempotently.
3. e2e's own `git check-ignore` used directory paths that don't exist (`dist/` patterns match directories only). Test fixed to use file paths.

## Known gaps (later phases)

- No rate limits, retention job or delete-now (P8). `/docs` (Swagger) is exposed through Caddy and `GET /demo/stream` is public (data-free, capped at 10 events).
- SSE follows by polling the `job_event` table every 0.5 s (fine for P0; LISTEN/NOTIFY later if needed).
- Upload writes use blocking file I/O in the event loop (64 KB chunks); revisit with large files in P2.
- procrastinate schema upgrades on version bumps are not handled (schema is applied once if absent); pin the version.
- Postgres has only `no-new-privileges`; the stock image needs more privileges than the app containers. Image tags are `:dev`; pgvector's `pg16` tag floats (pin by digest before production).
- cad-worker writes nothing yet; P2 needs a separate writable output mount (ADR-012).
- Worker and Postgres have no healthcheck beyond `pg_isready`.
