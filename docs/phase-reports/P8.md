## 1. What was built

### 1.1 Native adapter (ADR-018)

| Part | What it does |
|---|---|
| `apps/native-adapter` | `ApsAdapter`: 2-legged token, transient bucket, multi-part signed upload, translation job, manifest polling with back-off, download, delete in a `finally`. F3D → one STEP AP242 job; SolidWorks → SVF2 job, object tree + properties, then an OBJ job (millimetres) = 2 jobs. Service errors become short messages; an unexpected exception also returns a result and gives the count back |
| Record / replay | `C2B_APS_MODE=live\|replay\|record`. Replay and record are httpx transports keyed by `METHOD path` (+ output types for a translation job). Record redacts tokens and signed-URL query strings |
| Usage cap | `aps_usage` table; `reserve` is one atomic `UPDATE … WHERE jobs + n <= cap`; failed-before-upload gives the count back |
| Worker | New `native` queue (`lock="aps"`), status `converting`. A converted STEP is stored as a `cad` upload with `origin=converted`; SolidWorks meshes go to the cad-worker's new `mesh_extract`. Failure or cap with other inputs present: the job continues with them and says why; with only the native file it stops with the message |
| Consent | The API stores no native file without recorded consent (`409 consent_required`); consent is stored with a time and the wording version; the worker checks again. Unconfigured: `415 native_not_configured` with "Native conversion isn't set up on this server… export it as STEP" |
| Web | Consent dialog with the server's exact wording (default focus on Cancel, checkbox, usage shown), `converting` step in the progress panel, "converted by Autodesk" label, callout asking for a STEP AP242 export next to a SolidWorks file |

### 1.2 SolidWorks properties and mesh features

* `library/cad_props.yaml` (new, validated by a strict schema) maps property names (EN/DE) to `part_number`, `description`, `material`, `class`.
* `props_merge.py` matches properties to nodes by normalised name (`Plate<1>` = `Plate`), resolves a material text to a library code through its designations, drops placeholder values (`-`), carries `Custom…` properties as `custom.<name>`, and reports ambiguous names, unknown materials and unknown classes instead of guessing.
* Rules: a part number from CAD is kept as authored (`source=cad_meta`, `R-NUM-CAD`); the existing `R-CLS-C02`/`R-MAT-CAD` paths now actually fire (`CadNode.props` was never populated before).
* `cad-worker` `mesh_extract` (numpy only, runs in the sandbox): volume, area, oriented box, closed-surface check, GLB for the viewer. `mesh_based` shapes scale geometry evidence and mass confidence by `confidence.yaml: mesh.features_factor` (0.6), and mass gets `R-MSS-MESH` plus an open item. The mass is now a `Prov` (confidence and rule) for mesh shapes.

### 1.3 Library versions and admin page (ADR-019, ADR-020)

* **Pinning was only a label.** The API and the worker read the image's `library/`. Now `data/library/{versions,drafts,active}` is the store, every API endpoint, the worker and the exports resolve `job.library_version`, and new jobs take `active`.
* Admin API: versions, browse, draft, save file (YAML checked), validate (same checks as `c2b-library validate`), publish (changelog required, clean validation required, next `YYYY.MM.n`, atomic switch, also recorded in Postgres), diff, metrics. Disabled (404) unless `C2B_ADMIN_PASSCODE` is set. Audit rows for logins, drafts and publishes.
* Protection: Caddy basic auth on `/admin*` and `/api/admin/*` **and** a passcode session token (`X-Admin-Token`).
* Web `/admin`: login, Versions / Edit a draft / Compare tabs (Radix Tabs), file list with filter, monospace editor (Ctrl+S, unsaved warning, revert), check list with levels, publish dialog with changelog, diff with `+`/`−` signs (not colour alone). Linked in the top menu only when the server has admin on. Tokens only, so both themes work.

### 1.4 Hardening and deploy (ADR-021, ADR-022)

| Item | What |
|---|---|
| Rate limits | Per-IP token buckets (job creation, uploads, admin login, general); `429` + `Retry-After` |
| Retention | `job.expires_at` (30 days, extended on approval); sweep at start-up and hourly under an advisory lock; files first, then the row |
| Delete-now | `DELETE /jobs/{id}`; confirm dialog on the upload and review screens |
| Backups | `scripts/backup.sh` / `restore.sh` (database dump, `data/jobs`, `data/library`; rotation), nightly systemd timer |
| Monitoring | Deeper `/readyz` (database, free disk, library store), `/admin/metrics` (Prometheus text), worker healthcheck on the queue heartbeat, `scripts/healthcheck.sh` + 5-minute timer + optional webhook, JSON access log |
| Deploy | `infra/docker-compose.prod.yml`, `infra/Caddyfile.prod` (HTTPS, HSTS, `C2B_ENV=production` hides `/docs`), `scripts/deploy.sh` for a fresh x86_64 or arm64 Ubuntu/Debian VM |

### 1.5 Defects found on the way

* `cad_client.py` was left referring to an undefined variable after my refactor; ruff caught it.
* The adapter let a non-HTTP exception escape with the cap still counted (found by `verify_p8.py`); it now catches it, reports it and refunds.
* Mesh mass confidence was computed but never reached the BoM line (the existing `mass_confidence` was unused); mesh masses are now a `Prov`.
* **Regenerating the golden files overwrites hand edits.** `c2b-fixtures build` rewrote `B4`/`B6` expectation text that P5 had edited by hand (cassette keys). I reverted that and changed only the version string. Run `c2b-fixtures build --case B7` only; fixing the generator is a known gap.

## 4. Differences from the phase prompt and design docs

1. **B7 uses scripted APS responses, not recordings.** There are no APS credentials and the generator cannot write a real `.f3d` or `.sldprt`. `golden/B7_native/aps/` holds responses scripted from the documented API shapes (`INDEX.txt` lists them), the inputs are placeholders (a ZIP and an OLE header), and the converted STEP is B2's. `C2B_APS_MODE=record` writes real recordings (to a git-ignored path) when you have credentials. The case is marked `stand_in: true`.
2. **Library baseline is now 2026.11.1** (P8 added `cad_props.yaml` and the `mesh` factor; a loaded version is immutable). The only change to the existing golden files is that version string (14 files, one line each) plus the B7 rows in `golden/README.md`. This also closes the "library version not bumped" item from the P0–P6 review.
3. The library store lives under `data/library/` (read by the worker through its existing read-only `/data`), not a new Docker volume as first planned: one place to back up.
4. `ProblemDetail.code` gained `native_not_configured`, `consent_required`, `rate_limited`, `forbidden`; `JobStatus` gained `converting`; `UploadOut` gained `origin`; `JobOut` gained `expires_at`; `ShapeFeatures` gained `mesh_based`.
5. Admin token header is `X-Admin-Token`, not `Authorization`, because the basic-auth layer uses that header.
6. Pre-P8 jobs (version label not in the store) fall back to the image's library with a warning (ADR-019).
7. Proposed ADRs 018–022 added to `docs/08`; `docs/03`, `05`, `06`, `versions.md` and `docs/10` §0 updated.

## 5. Not verified, and known gaps

* **Nothing ran against real Autodesk.** The signed-S3 upload page of the APS docs returned 404, so that flow follows Autodesk's published OSS v2 API from memory. SolidWorks properties through SVF2 are likely but unconfirmed for real files, and the OBJ job on a model guid is my reading of the docs. The first real run may need small fixes; a recording will show them.
* **The free-tier allowance is unknown** (image only). Set `C2B_APS_MONTHLY_CAP` from your APS console.
* **New screens not opened in a browser:** consent dialog, delete dialog, `/admin`. They are typed, linted (jsx-a11y) and use tokens, but keyboard-only use, both themes, reduced motion and screen-reader behaviour were not checked, and there are no screenshots.
* **`scripts/deploy.sh`, backup/restore, the health timer and the production overlay were never run on a VM** (syntax check and `docker compose config` only). Caddy automatic HTTPS and `sysctls` for ports 80/443 are untested. The script installs Docker from get.docker.com when missing: read it first.
* **arm64:** the new dependencies (httpx, numpy for the cad-worker) were not built for arm64; amd64 images were built by `make e2e`.
* **Rate limiter is in memory** (correct for one API replica). Behind another proxy or CDN, `X-Forwarded-For` handling needs review.
* The admin audit log has no viewer; changing the admin passcode needs a restart; there is no "upgrade this job to the new library" action yet (it belongs with the re-run endpoint, ADR-017); backups still contain deleted jobs until they rotate out.
* A job deleted while a converted file is at Autodesk relies on the transient bucket (24 h) for any leftover.
* `description` from CAD properties is stored on nodes but not yet used by the description builder.
* Mesh features are volume, area, oriented box and a closed check only: no cylinders, wall thickness or helix, so classes that need them stay uncertain until a STEP is added.
* `c2b-fixtures build` still overwrites hand-edited golden text (1.5).
* Open owner decisions from the P0–P6 review that this phase did not touch: scripted (not recorded) LLM cassettes, a photo consent flag, archetypes never auto-applied.
