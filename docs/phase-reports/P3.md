Date: 2026-11-23. ## 1. What Was Built

### 1.1 Domain Models (`packages/domain`)
- **BoM Data Models (`bom.py`)**:
  - `BomLine`: Complete representation of an engineering BoM line with hierarchical identifiers (`id`, `parent`, `level`, `find_no`), CAD name and linkage, part number provenance, description with noun and modifiers, taxonomy classification (`cls`), standard-part designation, quantities (`qty_per_parent`, `qty_total`, `uom`), material and finish with provenance, calculated mass, make/buy recommendation (`make | buy | supplier_made`), flags (`phantom`, `buy_as_assembly`, `description_exact`), CAD measured volume, confidence score (0–1), rule IDs (`rule_ids`), open items (`open_items`), note, and deterministic explanation paragraphs (`explanation`).
  - `Designation`: Structured representation of recognized standard parts (`standard`, `family`, `size`, `length_mm`, `score`, `key`).
  - `BomDraft`: Container for a job's complete draft EBOM, library version, profile name, lines list, and aggregate statistics.
- **Export & Types (`export_schema.py` & `packages/ts-types`)**:
  - Registered `BomLine` and `BomDraft` in the JSON Schema export pipeline.
  - Generated TypeScript type declarations `BomLine.d.ts` and `BomDraft.d.ts`.

### 1.2 Deterministic Rules Engine (`packages/rules`)
- **Safe AST Evaluator (`evaluator.py`)**:
  - Secure evaluator for rule `expr` strings using Python's `ast` module.
  - Implements an explicit whitelist of allowed AST nodes (`BinOp`, `UnaryOp`, `Compare`, `Constant`, `Name`, `Call`).
  - Whitelisted safe mathematical functions: `abs`, `min`, `max`, `round`.
  - Rejects attribute access (`obj.attr`), subscripting, dunder variables, statements, comprehension expressions, and unauthorized function calls.
- **Rule Interpreter (`interpreter.py`)**:
  - Executes rule condition primitives against structured context: `name_matches`, `name_not_matches`, `feature_between`, `std_designation_family`, `class_is`, `parent_class_is`, `has_property`, `expr`.
  - Resolves rule files under `library/rules/*.yaml` (`classify.yaml`, `structure.yaml`, `mbom.yaml`, `gaps.yaml`, `validation.yaml`).
  - Returns `MatchedRule` records containing rule ID, stage, weight, action, and explanatory note.
- **Parametric Standard-Part Recognisers (`recognisers.py`)**:
  - Driven directly by standard tables in `library/standards/*.yaml` with dimensional tolerances ($\pm 0.5\text{ mm}$ for small diameters, $\pm 1.0\text{ mm}$ for lengths).
  - Implemented recognisers:
    - **Fasteners (screws & bolts)**: ISO 4762 (socket head cap screws), ISO 4014 / ISO 4017 (hex head screws/bolts), ISO 7380 (button head screws), ISO 10642 (countersunk screws).
    - **Nuts**: ISO 4032 (hex nuts style 1).
    - **Washers**: ISO 7089 / ISO 7090 / ISO 7092 / ISO 7093 (plain washers), DIN 127 (spring lock washers).
    - **Bearings**: ISO 15 radial ball bearings (deep groove series 60xx, 62xx, 63xx).
    - **Pins**: ISO 2338 (parallel dowel pins).
    - **Seals**: ISO 3601-1 (metric O-rings).
  - Outputs standard designation, metric size key, match score, and length.
- **Classification Ladder C1–C6 (`classifier.py`)**:
  - **C1**: Explicit user override (confidence 1.0).
  - **C2**: Authored CAD property (confidence 0.90, rule `R-CLS-CAD`).
  - **C3**: Standard-part recogniser match (confidence 0.85, rule `R-CLS-STD`).
  - **C4**: Name dictionary with tokenized matching against `library/synonyms/en.yaml` and regex patterns in `patterns.yaml` (confidence 0.60–0.80, rule `R-CLS-SYN`).
  - **C5**: Geometric evidence scoring (confidence 0.50–0.75):
    - Sheet metal detection via constant thickness and thin-plate properties (`sheetmetal.bracket`, rule `R-CLS-SHM`).
    - Cylindrical and turned part classification via rotational symmetry and outer cylinders (`machined.turned`, rule `R-CLS-TRN`).
    - Moulded plastic component classification (`moulded.plastic`).
  - **C6**: Context evidence boosting (e.g. specializing `electrical.motor` to `electrical.motor.ac_induction` in fan assemblies, rule `R-CTX-FAN`).
  - **Evidence Combination**: Uses noisy-OR probability calculation:
    $$C = 1 - \prod_{i=1}^{n} (1 - c_i)$$
    Evaluates against minimum confidence thresholds in `library/confidence.yaml`.
  - **L1 Fallback**: Returns placeholder question flag when confidence is below threshold, ready for Phase 4 human/LLM ladder.
- **Material & Mass Engine (`material_mass.py`)**:
  - Priority ladder: User override > CAD property > Datasheet > User BoM file > Class profile default > Unknown.
  - Automatically loads profile defaults from `library/profiles/default.yaml`.
  - Computes mass from measured CAD volume and material density:
    $$\text{Mass (g)} = V (\text{mm}^3) \times \frac{\rho (\text{g/cm}^3)}{1000}$$
    attributed to rule `R-MSS-VOL`.
  - Tracks open items when material or grade is assumed or unknown.
- **Noun-First Description Generator (`descriptions.py`)**:
  - Produces uppercase descriptions conforming to profile rules:
    - Standard parts: `NOUN, MODIFIERS, SIZE, STANDARD, MATERIAL FINISH` (e.g. `SCREW, CAP, SOCKET HEAD, M3X10, ISO 4762, STEEL 8.8 ZINC PLATED`).
    - Custom parts: `NOUN, DIMENSIONS, MATERIAL` (e.g. `BRACKET, 60X40X30 T2, MILD STEEL, COLD ROLLED (CRCA)`).
- **EBOM Structure & Roll-Up (`structure.py`)**:
  - Preserves hierarchical levels from the CAD assembly tree.
  - Generates sequential find numbers per parent (10, 20, 30...), placing standard catalog parts at the end when configured.
  - Multiplies instance quantities through intermediate parent assemblies down to total quantity.
  - Detects modelling phantoms (e.g. assemblies named `*_GRP` or `*_PHANTOM`) and marks `phantom = True`.
  - Flags purchased assemblies (`buy_as_assembly = True`) with make/buy recommended as `buy`.
  - Groups identical part occurrences under the same parent by shape signature.
- **Deterministic Explainer (`explainer.py`)**:
  - Generates transparent, human-readable markdown explanations for every BoM line by tracing rule IDs, geometric features, standard matches, and profile defaults. Zero LLM involvement.
- **Engine Coordinator (`engine.py`)**:
  - `build_ebom(extract, library, job_id, profile_name)` orchestrates the entire deterministic pipeline and compiles the `BomDraft`.

## 4. Architectural Notes & Deviations

1. **Non-Negotiable Rule 1 & 12 Compliance**:
   - Zero LLM calls in `packages/rules`. All outputs derive strictly from the library tables, geometric shape features, and deterministic YAML rules.
   - The expression evaluator uses pure AST tree inspection without Python's built-in `eval` or `exec`.
2. **Pydantic Model Field Aliasing**:
   - `BomLine` defines `cls` with `validation_alias="class"` and `serialization_alias="class"`. This allows seamless JSON serialization/deserialization matching golden contract schemas while enabling pythonic keyword instantiation in strict type checking.
3. **Noisy-OR Probability Formulation**:
   - Multiple classification signals (synonym tokens + geometric feature matches) are combined using standard independent noisy-OR formulation, preventing arbitrary over-confidence while rewarding multi-source confirmation.
4. **Git Hygiene**:
   - Working tree contains all Phase 3 source code, migrations, and verification tooling. No commits or pushes made (Rule 2).
