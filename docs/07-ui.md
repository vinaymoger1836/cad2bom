# 07 — User flow and UI

## 1. Flow

| Step | Screen | What the user does | What the system does |
|---|---|---|---|
| 1 | **New BoM** | Product name, short description, product type (optional, searchable list), annual volume (optional), variants (optional) | Creates the job and its link |
| 2 | **Upload** | Drop CAD, photos, BoM files, datasheets. For SolidWorks/Fusion files: consent to conversion | Type and size checks, upload progress, consent recorded |
| 3 | **Confirm BoM file mapping** (only if a BoM file was uploaded) | Check the proposed column mapping on a preview; fix with dropdowns | Header rules (LLM only if ambiguous, marked) |
| 4 | **Building** | Watch progress | Steps of doc 02 §3 streamed over SSE: "Reading CAD: 214 parts, 37 unique", "Recognised 52 standard parts", "3 questions" |
| 5 | **Review** (main screen) | Answer questions, accept/reject suggestions, edit lines, inspect parts in 3D, chat | Partial re-runs on every answer or edit |
| 6 | **Approve and export** | Approve (blocked until questions and suggestions are resolved); download XLSX/CSV/JSON/PDF | Validation, version freeze, exports |

## 2. Review screen layout

- **Top bar:** product, job status, BoM version, library version, confidence summary (High / Medium / Low counts), buttons: Approve, Export, Re-run.
- **Left: questions and suggestions panel**, sorted by impact (blocking first, then by number of lines affected). Each card: plain question, evidence chips (CAD node, file row, photo, page), answer controls (choices, number with unit, text), "why am I asked?" tooltip.
- **Centre: BoM table** (TanStack Table, virtualised):
  - Toggle EBOM / MBOM / Purchased items / Excluded.
  - Indented tree with expand/collapse; columns per profile; inline edit (edits become `source=user`, shown with a person badge).
  - Badges: source (CAD, file, standard, rule, AI, you), confidence (H/M/L colour + text), review status, open-item count.
  - Filters: low confidence, AI-sourced, suggestions, by class, by make/buy.
  - Row click → right panel details.
- **Right: 3D viewer + line details** (React Three Fiber, GLB):
  - Selecting a line highlights its instances (others dimmed); clicking a part in 3D selects its line.
  - Details tab: every field with its source, confidence, rule ids ("explain this line" in plain words), evidence links, history of edits.
  - Toggle: show excluded bodies; isolate; section plane; fit.
- **Chat drawer (agent):** "Why is this a socket head screw?", "Group all fasteners by size", "Mark the motor as a purchased assembly". Answers are grounded in the job data; any change the agent proposes comes back as a suggestion card the user accepts, so nothing changes silently.

## 3. Wording and accessibility

- Plain language everywhere; every technical term has a tooltip (EBOM, MBOM, phantom, find number, refdes, designation, confidence).
- Each step has a "What happens here" box and a short Q&A at the bottom (same pattern as the platform's MVP pages).
- Keyboard: table navigation with arrows, Enter to edit, Esc to cancel; questions panel reachable with a shortcut; visible focus; ARIA roles on tree grid and dialogs.
- Light and dark themes from tokens; 3D viewer background and highlight colours per theme; reduced-motion respected for progress animations and camera moves.
